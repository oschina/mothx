## 1. 逐项发现(校准后)

### F1 [撤回] HistoryView 徽标让本地缓存盖过 canonical `lastRun`——复核后判定为「有意为之且有测试钉死」,不改

- **位置**: `desktop/renderer/src/views/HistoryView.tsx:28-29`
  ```ts
  function historyStatus(session, rememberedStatus?) {
    const status = rememberedStatus || (session._meta?.lastRun?.active ? 'running' : session._meta?.lastRun?.status);
  ```
- **现象**: 取值优先级是「持久化缓存 `store.sessionStatus` > ACP `lastRun`」。当本地缓存是旧的(例如该会话此后在别处重跑、终态改变),历史页徽标会显示过期的缓存值,与 ACP 权威状态不一致。
- **对照(说明侧边栏是对的)**: `components/Sidebar.tsx` 的 `sessionStatus()` **优先** `session._meta.lastRun`(有 `runStatus` 能力时),否则看内存 `isSessionRunning`,最后 `idle`,并不读持久化缓存。所以侧边栏不存在这个问题——上一轮口述 review 里「侧边栏会误标」的说法**是错的**,已在本记录中更正。
- **影响**: 仅历史页徽标的展示口径;不影响输入框、不锁 composer(`completed`/`failed` 都不在 LIVE 集合)。低危。
- **复核更正(撤回本条)**: 进一步核对 `HistoryView.test.ts:7-17` 发现,当前优先级是**刻意设计且有测试钉死**的——测试名「live ACP run status badge with durable lastRun fallback」、断言消息「the realtime ACP status projection must take precedence while history reloads catch up」「the durable listAll lastRun projection must remain the fallback」表明:`rememberedStatus` 是由 `_mothx/session_event run_status` 实时写入的「实时投影」,而 `lastRun` 是 `session/listAll` 的分页快照(下次 reload 前可能滞后)。让实时值优先、快照兜底是正确取向;反转它会推翻一个有意的决定并弄坏测试。**故 F1 不修。**

### F2 [低] 死字段 `pinnedSessions` 与过时 README 措辞

- **位置**: `desktop/main/store.ts`(interface/DEFAULTS/load/set)、`desktop/renderer/src/core/api.ts:68`(StoreData)、`desktop/renderer/src/core/state.ts:201`(默认 store)、`desktop/main/acp-client.test.ts:46,61`(唯一用到它的测试)、`desktop/README.md`(「置顶任务……保存在 desktop-store.json」)
- **现象**: 生产代码没有任何地方读写 `store.pinnedSessions`。真正的置顶走 canonical ACP:`sessions.ts` 的 `isPinned()` 读 `session._meta.pinned`,`togglePin()` 调 `mothx/session/setMeta`(受 `sessionMeta` 能力门控)。该字段只活在 schema/默认值/一条测试断言里。
- **为什么值得删**: AGENTS.md 明确把「pinning」列为 canonical ACP/Runtime 状态、**不得**落入 `desktop-store.json`。留着一个名为 `pinnedSessions` 的本地字段是个「以后有人误用、重新引入本地置顶源」的隐患;README 那句描述也与现状不符。
- **影响**: 运行期零影响(无人读)。纯卫生 + 文档准确性。
- **修复方向(本轮落地)**: 从 store schema/默认/load/set、渲染层 StoreData 与默认 state、对应测试断言中移除 `pinnedSessions`;订正 README,把「置顶任务」从「本地保存的 UI 状态」清单里去掉,并点明置顶是 ACP `setMeta` 的 canonical 状态。

### 不改的项(记录理由,避免后续重复 review)

- **`sessionStatus` 本地缓存本身**: 它是「侧边栏/历史页状态点在 ACP `session/listAll` 未逐行下发终态时」的展示兜底,属已记录的迁移桥(README 指向 gap proposal P1-4/P1-5),有 400 条上限自限。F1 修好取值优先级后,缓存不再盖过 canonical,残留风险可接受。openSession 对「从未本地跑过」的会话默认填 `completed` 只是 header chip 文案猜测,不改。
- **delete 不清 `store.sessionStatus[sessionId]`**: 有上限自限,纯展示,不改。
- **Linux 打包关 renderer sandbox**(`main/index.ts:155`): AppImage `nosuid` 下的常规且已注释取舍,`contextIsolation` 仍开、`nodeIntegration` 仍关。属背景信息,非问题。
- **`runtime-binary.ts` 遗留候选路径**: 兼容性 fallback,留着无害。
