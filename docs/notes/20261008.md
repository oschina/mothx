## 2. 逐项观察（均不阻塞，不改）

### F1 [低] 投影守卫对「类型推断得到的快照」不生效

- **位置**: `internal/architecture/session_projection_guard_test.go:84-104`
- **现象**: 字段写入检查仅在文件「提到」`SessionExecutionSnapshot` 类型名时启用（`mentionsSnapshot`）。适配器若写 `snap, _ := agentruntime.InspectSessionExecution(...)` 再 `snap.Busy = true`，文件里没有类型名字面量，守卫不会报错——比 AGENTS.md 声称的「禁止写 `Busy/CanSubmit/CanCancelLocal`」弱。
- **现状**: 全仓当前无一是例（grep 复核），故无即时风险。记录以免后续误以为守卫已完全覆盖；若要补强，可按「对 `Inspect*` 调用结果变量做轻量数据流追踪」或「对任意选择器字段写入做白名单」。

### F2 [低] ownership 快照与 release 的发布顺序可能短暂「复活」已释放条目

- **位置**: `internal/session/runtime_lease_bus.go:425-453`（`publishOwnershipSnapshots`）、`runtime_lock.go:528-569`（`release`）
- **现象**: `publishOwnershipSnapshots` 在 `bindingMu.RUnlock()` 之后才发送；并发 `release()` 可能先发 `released`、后发快照（`Seq` 在各 goroutine 发送时才 `Add`，无全局定序），接收端 `ingestRuntimeOwnership` 因 `seq` 更大而重新写入该条目。影响仅限缓存提示：对端可能把刚释放的会话短暂投影成 `external/busy`，最长到 30s 存活窗口。权威（CAS/DB 回读）不受影响。
- **建议（若后续修）**: 在 `bindingMu` 持锁内完成「判 `released` + 复制 + 发送」，或让快照 `Seq` 直接复用条目在 release 时的序号。

### F3 [低] 缓存快路径使「进程被 kill -9」的孤儿恢复最多延迟约 30s

- **位置**: `internal/agentruntime/execution_ownership_projection.go` + `execution_snapshot.go:245-256`（`InspectSessionExecution`）
- **现象**: owner 被杀后不再广播快照，但其条目在 `runtimeOwnershipLivenessWindow`（30s）内仍为 `Fresh`，此窗口内 `InspectSessionExecution` 走缓存、跳过会触发 `wakeRecoveryCoordinators` 的 DB 路径，于是孤儿恢复被推迟到窗口过期后。属方案已记录的取舍（用存活窗口而非 `ExpiresAt`，以避免长任务被误判陈旧）；仅记录该延迟上界。

### F4 [低] `ResolvePath` 现在返回符号链接规范化后的路径，行为面变化

- **位置**: `internal/tools/tool.go:457-465`
- **现象**: 返回值由「clean 后的输入」变为「canonicalize 后的真实路径」。`TestRegistryResolvePath`（`coverage_test.go:143`）硬编码 `/home/user/project/src/main.go`，仅当祖先目录无符号链接时成立；在被符号链接的工作目录/临时目录（如 macOS `/tmp`→`/private/tmp`、部分发行版 `/home` 为 autofs）上会得到不同字面量。功能与安全正确（这正是围栏目的），但工具输出/检索结果中的路径字符串会随之规范化，可能与用户输入不一致。

### F5 [低/信息] `LeaseTokenIdentity`（fencing token 哈希）随 ACP 响应新暴露

- **位置**: `internal/agentruntime/execution_snapshot.go:58,277`（`LeaseTokenIdentity = lease.TokenHash`）、`internal/acp/acp.go:593,2439-2446,3898`（本轮新增 `execution` 字段）
- **现象**: `5d68a047` 把完整 `SessionExecutionSnapshot` 加入 `session/load`、`session/resume` 与列表 `_meta`，于是 `execution.leaseTokenIdentity` 也进入 ACP 载荷。该值是 CAS 围栏用的 token 哈希（serve HTTP 响应此前已携带，非本轮首创），ACP 客户端与进程同主机、属既定信任域，故非新边界问题；但它本质是进程内围栏身份，cache 快路径本就留空，客户端也不需要。
- **建议（若后续收紧）**: 在适配器投影处 `json:"-"` 或掩码化 `LeaseTokenIdentity`，使其仅留在进程内。

### F6 [信息] `IsRetryable` 新增子串匹配可能过度重试

- **位置**: `internal/provider/retry.go:96-105`
- **现象**: 新增 `"internal error"`/`"unavailable"`/`"resource_exhausted"` 任意位置子串匹配，理论上会重试「文案里恰好含这些词」的永久错误；有界退避限制其代价。属既定取舍，记录。

### F7 [信息] `InspectSessionExecutions` 注释称「bounded batch」但无显式上限

- **位置**: `internal/agentruntime/execution_snapshot.go:434-455`
- **现象**: 逐 session 调 `InspectSessionExecution`（每次 DB 打开/读取或 cache 命中），无显式条数上限，实际由调用方分页保证。注释略强于实现，记录。
