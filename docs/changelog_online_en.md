# Changelog (Current Version)

This file contains the changes for the **current version only**. The full history of all versions lives in [docs/en/changelog.md](en/changelog.md).

## v1.3.105-pre-1

### ✨ New Features

- **Sessions reject unusable working directories early.** `internal/session` is the single owner of working-directory validation, with the Runtime API delegating to it. Session creation, reopening, rebinding, ACP `mothx/session/setWorkDir`, and channel session resolution now require an existing absolute directory before persisting or assembling sandbox and tool resources. An ACP same-directory request no longer detaches a usable runtime when its directory has disappeared, and a channel run validates the bound session's persisted cwd rather than the platform default.
- **Desktop uses an explicit draft-directory model.** The legacy workspace-default fallback and settings panel were removed. Quick-start drafts receive one process-local `mkdtemp` scratch directory, while a New Task draft remains unset until its native picker or worktree action supplies a directory. Picker history is only a convenience for the next dialog; draft state carries a generation so a stale quick-start, picker, or ACP completion cannot overwrite a newer New Task.
- **Runtime coordinates local session submissions.** `SessionRuntime` owns one `(database identity, session ID)` FIFO `SubmissionCoordinator`, and `ExecutionRuntime.Completion` is the authoritative completion barrier. TUI queued input, ACP prompt admission, Channel/Cron/ESM/Knowledge admission handoffs, shutdown, cancellation, and structured local/external busy classification now share that lifecycle instead of polling lease errors or starting a successor from an Agent finish event.

### 🐛 Bug Fixes

- **Rotating a bound channel session preserves its durable directory.** Rotation inherits the existing session's persisted cwd instead of falling back to the platform default, and its fenced compare-and-set compares canonical paths so an equivalent stored form such as a trailing separator still succeeds while a real concurrent change is rejected.
- **Feishu tool-image cleanup is concurrency-safe.** Each delivery materializes images beneath a unique private temporary directory and removes the whole directory on every exit path, preventing parallel runs from collecting one another's files and leaving no image bytes behind in the work directory.
- **Session EventStore migration has one unified entry point.** Migrating an old session to the EventStore used to happen only from `SessionRuntime.BindSession`, so entry points that assemble sessions directly — ACP/Desktop, channels, ESM, and background runs — left old sessions on the legacy SQLite transcript and kept new sessions on the `sqlite` content store. `BindSession`, `AttachSessionResources`, and `Builder.Build` now call the same migration entry point, `Manager.MigrateToEventStore`, with no per-site wrapper or special handling: an existing session is exported to the session-scoped EventStore and a new one is flipped to it regardless of which adapter opened it, with no divergence in content ownership. The entry is now safe to call unconditionally — while another owner is running the session it is a successful no-op instead of an attach-blocking error, the self-consistent legacy store keeps serving, and a later idle attach completes the migration; only corrupt or unreplayable legacy data fails closed.
- **Stopping a session no longer fails while its run is terminalizing.** A terminal write that failed after the durable Run entered the committed `terminalizing` window left its row in a state only a terminal transition may advance, yet the Web UI stop path still tried to force `terminalizing` -> `cancelling`, which the run store rejects — so the request returned `persist run cancellation: invalid session run transition "terminalizing" -> "cancelling"` and the run looked permanently uncancellable. `ExecutionRuntime.CancelDurable` and the shutdown cancel path now detect a prepared/terminalizing terminal transaction, skip the illegal cancelling write, accept the cancellation (still cancelling the loop), and restart the prepared terminal write when its retry had stopped, so an interrupted run can still reach a terminal state.
- **Appending to a session's EventStore is no longer quadratic in transcript size.** EventStore appends used to re-read the whole log several times per batch — a health inspection, an idempotency scan, a next-sequence scan, and a commit-time validity scan — so append cost grew with the session's accumulated content (512 entries: 3.8 ms → 178 ms per batch, 5.7 s cumulative) while the legacy SQLite path stayed flat. The health gate now trusts the process-local append-state cache whenever it is fresh for the current physical revision and checks only that every SQLite intent is committed; `NextSequence` reads the cached cursor; the idempotency probe uses the projection index and reads the full committed transcript only on a real retry; and `CommitEventIntent` accepts the just-fsynced batch instead of rescanning. Appends are now constant-time in transcript size (same probe: ~3 ms per batch, 0.30 s cumulative, about 19x faster), with the intent/lease protocol, fencing, and recovery verification unchanged. A deterministic regression test pins that appending to a warm session performs no whole-log scans.
- **Opening a brand-new Web UI session no longer reports `session_not_found`.** A server-allocated Web UI session is persisted only when its first run starts, but the run-event, capability-event, and sub-agent lookups rejected that still-unpersisted id, so the Web UI surfaced `session_not_found` while creating a session. Those three lookups now project an empty result for an allocated id — matching the trajectory, capabilities, runtime, and message lookups — while an arbitrary unknown id is still rejected.
