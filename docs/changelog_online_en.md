# Changelog (Current Version)

This file contains the changes for the **current version only**. The full history of all versions lives in [docs/en/changelog.md](en/changelog.md).

## v1.3.109

### 💥 Behavior Changes

- **Desktop (Electron) is deprecated; MothX Native is the primary desktop client.** The `desktop-release.yml` workflow no longer runs on version tags and remains only as a manual compatibility bridge that can never mark a release as latest; `native-release.yml` is the sole automatic publisher of desktop artifacts (Linux binary/deb/tar.gz/PKGBUILD, macOS dmg, Windows exe/setup). The root Makefile help lists Native first and marks the Desktop targets deprecated. New bilingual guides (`docs/en/native.md`, `docs/zh/native.md`) cover installation, the feature surface, and migration; `desktop.md` carries a deprecation banner with a named removal condition (delete `desktop/` and its entry points once a full release cycle ships no Desktop assets and no manual compatibility build was needed). No canonical data moves: sessions, transcripts, and configuration stay in the shared Runtime, so Desktop users switch shells without migration.

### ✨ New Features

- **A Router ACP profile can set the external worker's default model.** `acpAgents` now accepts an optional `model` field, applied by the Runtime when it creates the remote worker session. MothX uses the standard ACP `configOptions` model option (`category: "model"`) and falls back to the deprecated `models`/`session/set_model` wire only for a worker that advertises no modern option. Leaving `model` empty preserves the third-party Agent's own default behavior. A configured model that the worker does not offer fails the delegation with the available choices instead of silently running a different model, and a resumed session with no returned catalog keeps the Agent's persisted selection. The profile's model is editable from the TUI `/router` panel, the WebUI Router Worker settings, and Desktop Router Workers, and is projected in the shared Runtime catalog.
- **Router now has one worker-management signature and a loopback MCP bridge.** Router mode registers exactly one tool, `delegate_worker_mgr`, whose `delegate`/`spawn`/`status`/`list`/`send`/`wait`/`destroy`/`integrate`/`answer` actions cover the whole external ACP worker lifecycle; the local `delegate_subagent` and `subagent_*` tools no longer appear in Router and no longer advertise Router-only fields. A local stdio worker can receive one MCP server, `mothx-worker`, in `session/new|load|resume`, authenticated by an in-memory per-child bearer token. Its single `worker_mgr` tool supports `context`, `report` (notice/progress/finding), and `ask` (durable `DecisionQuestion` answered by the lead through `delegate_worker_mgr(action=answer)`), with bounded bodies, per-child rate limiting, dedupe keys, and session-scoped JSONL evidence (`worker-messages/<sessionId>/worker_messages.jsonl`, removed with the session). Findings enter lead context as `[WORKER_FINDING]` and may wake an idle lead; notice/progress never do. The bridge binds `tcp4 127.0.0.1:0` lazily, never uses stdio/SSE/public URLs, projects `mcpBridge=unavailable|unreachable|disabled` without blocking a task, including when bridge registration or listener startup fails. A token lives for the worker's remote session, not one turn: a post-terminal bridge call returns a `child_terminal` MCP tool error and the next `send` re-enables the same credential, while destroy/close, session shutdown, or process exit revokes it. The `delegate_worker_mgr` description publishes a capability summary derived from the same resolved state (report/ask, attachments, write, terminal, resume) and names why the bridge is unavailable. Worker activity is projected read-only in the TUI `/router` panel, ACP `mothx/worker/messages`, WebUI `GET /api/sessions/<id>/router`, and the Desktop Router composer; only the lead can answer a question. Profile `driver`, `mcpBridge`, and `capabilityOverrides` are editable from the TUI panel, WebUI Router Worker settings (`PATCH /api/acp/profiles`), and Desktop Router Workers settings (`mothx/manage/acp/profiles/patch`). `mothx doctor` now also verifies that the listener closes after its last token. See `docs/en/tools.md` and `docs/en/configuration.md`.

- **New Gitee/Moark Model: `hy4`**
  - Added `hy4` to the `gitee` and `moark` providers: a reasoning model with a 1M context window and text-only input, using the `deepseek-v4.1` reasoning-effort scale with no default max_tokens.

- **New Xiaomi MiMo Token Plan Model: `mimo-v2.6-pro-ultraspeed`**
  - Added `mimo-v2.6-pro-ultraspeed` to all three MiMo token-plan channels (`xiaomi-token-plan-ams`, `xiaomi-token-plan-cn`, `xiaomi-token-plan-sgp`). The faster variant of `mimo-v2.6-pro` keeps a 1M-token context window, a 128K-token maximum output, reasoning support, and multimodal (`text,image`) input.

- **New Volcengine Model: `deepseek-v4.1-flash-economy`**
  - Added `deepseek-v4.1-flash-economy` to all three Volcengine providers — `volcengine`, `volcengine-agentplan`, and `volcengine-codingplan` — with a 1M context window, reasoning support, and text+image input. The standard channel sends 262K max_tokens; the two plan channels send 100K.

- **New Volcengine Model: `glm-5.4`**
  - Added `glm-5.4` to all three Volcengine providers — `volcengine`, `volcengine-agentplan`, and `volcengine-codingplan` — with a 1M context window, reasoning support, and text+image input; it sends no default max_tokens, so the provider default applies.

- **New Gitee/Moark Model: `glm-5.4`**
  - Added `glm-5.4` to the `gitee` and `moark` providers: a reasoning model with a 1M context window, text+image input, and a 131,072-token output ceiling.

- **New Gitee/Moark Model: `mimo-v2.6-pro-ultraspeed`**
  - Added `mimo-v2.6-pro-ultraspeed` to the `gitee` and `moark` providers: the faster variant of `mimo-v2.6-pro` keeps a 1M-token context window, a 128K-token maximum output, reasoning support, and multimodal (`text,image`) input.

- **The Tencent Cloud plan now exposes only `hy4` and `hy4-flash`.**
  - The `tencent-hy-plan` and `tencent-hy-plan-anthropic` presets now list `hy4` and `hy4-flash` instead of `hy3`. `hy4` is text-only and `hy4-flash` accepts text and images; both support reasoning, carry a 1M context window, and keep a 65,536-token output ceiling.

- **The Alibaba Cloud Token Plan preset now targets the Qwen AI endpoint and a refreshed catalog.**
  - `alibaba-token-plan` now uses `https://token-plan.maas.qianwenaiapi.com/compatible-mode/v1` and ships `auto`, `qwen4-max`, `qwen3.8-max`, `qwen3.8-flash`, `deepseek-v4.1-flash-1017`, `deepseek-v4.1-flash`, and `glm-5.3` instead of the previous Qwen/Kimi/DeepSeek/GLM/MiniMax list. The Qwen and DeepSeek entries accept text and image input with a 1M context window, `qwen4-max` uses the native Qwen thinking switch, and `glm-5.3` keeps a 131,072-token output ceiling. The built-in `bailian` vendor adapter also detects the new domain automatically.

- **DeepSeek sessions can use native conversation titles.** When the resolved provider targets `api.deepseek.com`, the first model request of a titleless session now opts into DeepSeek's in-band `title` extension across the Chat Completions, Responses, and Anthropic Messages protocols. Agent Core captures the returned title (or falls back to the first user message when a refusal or error omits it), and the shared Runtime persists it once as an `auto` session title. Serve publishes `title_updated`; TUI, CLI, WebUI/API, ACP/Desktop, channels, and the public SDK all reuse the same Runtime path, so no adapter gains a second title request or generator. Serve keeps its existing separate title call for providers without the extension.

- **MothX Native closes the remaining Desktop parity gaps and fixes background layering.** Native now projects the canonical `subagent` lifecycle events into inline child cards, a per-session live roster (bounded at 200, running children kept) with a running/total header count and failure dot, and re-reads the authoritative `mothx/subagent/list` on terminal events and session load; background teams keep updating their own cached session. Plans carry the Runtime's `mothx.dev` title/note annotation into the side panel, card, and export; a collapsed streaming thought shows a compact live tail preview; tool text/diff ingestion is bounded like Desktop (20k/40k chars). Appearance gains the app-wide/home-only background scope with a readable theme veil, the launch quick-start scratch directory plus recent-directory picker history in the composer workspace menu, and automatic rollback when a user-selected runtime binary fails to start or initialize. Acceptance renders over a busy photo-like background caught and fixed a paint-order bug (MyGo paints absolute children above flow siblings, so the background layer hid the whole shell); negative ZIndex layering plus pixel-probe and headless regressions now pin image/veil/shell order in both themes and scopes.
- **MothX Native matches Desktop's New Task directory contract and completes elicitation forms.** A New Task draft no longer inherits the previous directory: it stays unset until the native picker (or a worktree action) supplies one, the shell asks at creation and again at send time, and cancelling keeps the draft instead of sending into an unknown cwd; the launch quick-start scratch remains the only no-ask default. While the draft has no directory, the provider/model menu is projected from `mothx/manage/providers/list` (configured providers first, catalog order kept, draft > existing > default preference) because `draft-config-options` requires a cwd. Multi-property `elicitation/create` schemas now render one input/enum field per property and answer with content keyed by property name; single-property and replayed object-enum schemas keep working, and an empty form declines.

### ♻️ Runtime and Architecture

- **ACP worker capabilities are now a typed, resolved model.** `internal/agentruntime/workerdriver` owns `WorkerCapabilities`, an explicit `generic-acp` adapter, and the profile ∩ advertised ∩ policy resolver; business code reads capabilities instead of probing raw `agentCapabilities` maps. Profiles gain optional `driver`, `mcpBridge`, and tighten-only `capabilityOverrides`. Resolved capabilities, degradations, and bridge state are persisted on `session_child_runs` (migration 58) and projected in child metadata. `mothx doctor` now checks loopback `tcp4` bindability and profile driver/bridge/override validity. `internal/architecture` guards the workerdriver leaf boundary and forbids driver-identity branches in business code. Real interop on 2026-11-10 verified OpenCode 2.0.16 and codex-acp 0.16.0 against the loopback bridge (OpenCode produced a real `worker_mgr` finding, codex-acp completed the MCP handshake); both were described by `generic-acp`, so no unverified flavor was added.

### 🐛 Bug Fixes

- **Gateway-hosted MiMo models replay `reasoning_content` with tool calls.** MiMo requires an assistant message that carries `tool_calls` to replay its `reasoning_content` on the next request. The requirement was previously detected only from the `xiaomimimo` base URL, so `mimo-*` models served by aggregators (B.AI, Gitee/Moark, OpenRouter, ...) could omit the field when the session had no recorded reasoning. MiMo model IDs are now recognized too, even when the gateway catalog does not list the model, and replayed assistant messages receive an empty `reasoning_content` placeholder when no reasoning was recorded.

- **Thinking switches and reasoning effort now match each vendor's documented contract.** An explicit thinking-off now sends `thinking: {type: "disabled"}` for DeepSeek Chat Completions/Anthropic Messages and `enable_thinking: false` for Qwen hybrid models instead of silently leaving thinking on, DeepSeek V4.1 uses `reasoning_effort: "none"` on the Responses API, and GLM effort maps to `low`/`high`/`max` so `medium` is never sent. DeepSeek effort follows its documented scale (`minimal`/`low` → `low`, `medium`/`high`/`xhigh` → `high`, `max` → `max`), gateway Qwen3.5+ and GLM model IDs are detected for thinking-format resolution, and a configured model list no longer inherits `compat` from the built-in preset at the same slice index.

- **MothX Native run and transport reliability fixes.** Session load and session-list responses now carry a connection generation, so a slow or failed load for a session the user already left cannot clear another session or reuse its cached transcript, and a session-list refresh requested while one is in flight is re-queued instead of silently dropped. The ACP client stores its child pointer atomically, bounds ordinary requests with a 5-minute deadline (`session/prompt` stays unbounded), and closes the child through the owned `os.Process` handle so a reused PID cannot be killed. Stale provider/draft-config responses are ignored after reconnect, and SkillHub icon fetches reject loopback/private/link-local targets at both URL validation and dial time. Native feature packages gained guard tests, and a cross-module wire test now executes the real management handlers and checks that every Native response key still matches the Runtime contract.

- **MothX Native ACP transport and connection lifecycle fixes.** The ACP client now owns its child's stdout/stderr pipes and lets the reader drain them before pending calls fail, so a response the Runtime writes just before exiting is no longer lost (it was lost in about a third of exits on a multi-core machine). A line longer than the reader accepts fails the connection and goes through the normal restart path instead of silently leaving a live child that nothing reads. Connection attempts are serialized: a request that arrives while another attempt is still handshaking supersedes it, a superseded attempt's failure can no longer turn a healthy connection into an error card or schedule a restart, and a replaced child is always stopped instead of outliving its connection with the Runtime scheduler still running in it.

- **MothX Native transcript and prompt fixes.** Live text chunks always append, so a code fence or a repeated token is no longer corrupted by a prefix heuristic; a history replay is merged into the task's cached transcript instead of appending a second copy of every turn that streamed live while the task was open. A prompt's completion and failure apply only to the task it was sent from, so a long run that ends after the user switched tasks no longer marks the open task idle or writes into its transcript, and a cancelled run's late answer cannot end the run that followed it. A session created from a draft no longer pulls the shell back when the person already opened another task, and a failed send returns the unsent text and attachments to an empty composer instead of losing them. Pending decision cards close when their run ends, an attachment without a caption can be sent as it can on Desktop, and reconnecting while a diagnosis is running no longer leaves the button busy.

- **MothX Native settings and management fixes.** Saving application settings keeps the exact text of approval and path entries: an allow prefix such as `go ` is no longer widened to `go`, and an untouched list is no longer reported as changed. MCP arguments round-trip through a quote-aware field instead of being split on whitespace, so an argument that contains a space survives an edit. Embedded attachments stay under the Runtime's 10 MiB request limit; a larger prompt used to wait forever for an answer that never came. Superseded provider, cron, and knowledge-base actions release their busy flags instead of leaving buttons disabled until the panel was reopened, connection diagnostics carry identifiers rather than Chinese display text, and the native release workflow injects the version into the symbol the binary reads.

- **TUI queued prompts now have one scheduler and a stable session binding.** The TUI no longer keeps a second queue/scheduler next to Runtime's `SubmissionCoordinator`: every interactive prompt is registered synchronously before the run starts, prompts staged during the first-session bootstrap are flushed into the coordinator once the session activates, slash commands are rejected while busy instead of being queued and sent to the model as text, and staged attachments stay with the prompt that owned them. A session change retires the old coordinator and clears its projections, so a queued prompt can never run in a different session.
