# Changelog (Current Version)

This file contains the changes for the **current version only**. The full history of all versions lives in [docs/en/changelog.md](en/changelog.md).

## v1.3.108

### 💥 Behavior Changes

- **Router no longer uses profile-level `roles` or `writeRoots`.** Role is now an optional per-delegation semantic hint (default: `investigate`), and `write_scope` is optional task metadata used for prompting, audit, and overlap checks. A write role no longer requires a scope, but MothX's optional `fs/write_text_file` bridge is offered only when a task declares a non-empty scope. This is a correctness fix, not a claim of containment: an external ACP Agent runs its own tools, so neither setting can confine its writes. Managed per-child worktrees plus `subagent_integrate` remain the real write-isolation path, and base-workspace parallelism remains explicit operator trust. Existing `settings.json` values still parse but are ignored and no longer appear in the TUI, Runtime catalog, WebUI, or Desktop. A MothX self-ACP worker can now be configured with just its command, enabled flag, and permission policy.
- **The lead agent loop's iteration budget starts at 400 turns and can be renewed up to 600.** The main loop's default initial iteration limit is now 400 (previously 200) and its renewal ceiling is 600, so a long task that keeps making progress runs twice as long before the budget-pressure notice appears. The `extend_budget` policy keeps two grants, and the per-grant step is now derived from the Soft->Hard headroom so the grants exactly fill it (400 -> 500 -> 600); a run that never renews simply stops at 400. The companion limits scale with it: the stuck-detection silent-turn threshold is now 195 (was 95), channel runs default to `maxTurns` 180 (was 90), and sub-agent / workflow-worker `max_iterations` defaults to 100 (was 50). A caller that supplies an explicit soft limit still gets the conventional 2x hard ceiling.

### ✨ New Features

- **Added the SenseNova (商汤日日新) provider.** The built-in `sensenova` preset targets the SenseNova token-plan endpoint `https://token.sensenova.cn/v1` with the OpenAI-compatible `openai-chat` API, reads `${SENSENOVA_API_KEY}`, registers a `sensenova` vendor adapter for `sensenova.cn` base-URL auto-detection, and ships `sensenova-6.8-flash` and `sensenova-6.8-flash-lite`, each with a 1,000,000-token context window, a 131,072-token output ceiling, reasoning support, and `text`/`image` multimodal input.
- **Router mode is still a beta (preview) mode.** Router and the `acpAgents` profiles that feed it are evaluation features, not a production contract: the tool surface, the profile schema, and the lifecycle may change in any release without a compatibility migration path, and Router stays deliberately excluded from `defaultMode` (a stray `defaultMode: router` still resolves to read-only `plan`). Use Router to try external ACP workers on a scratch session, and do not depend on it for unattended or production workflows. The TUI, CLI, WebUI, and Desktop entry points all project the same Runtime-owned behavior, so the evaluation covers every entry point equally. Every Router surface now says so: the TUI status bar, mode cycle, `/router` panel, and `/mode` output, plus the WebUI and Desktop composers, all carry a beta / preview marker.

- **Desktop can now enter Router mode.** The composer gained a Router control that lists the configured external ACP workers and binds the selected ones to the session. Desktop stays a pure ACP projection: the catalog comes from the existing `mothx/manage/acp/profiles/list` and the activation from the new additive `mothx/manage/router/activate`, both of which delegate to the shared Runtime activation path, so Desktop cannot reach a Router state the TUI, CLI, or WebUI could not. The control is gated on the new `manageRouter` feature key and the selection never enters Electron-owned storage.
- **The WebUI can now enter Router mode.** The composer gained a Router button that lists the configured external ACP workers and binds the selected ones to the session. The catalog comes from `GET /api/acp/profiles`, which is the same Runtime catalog the TUI panel renders, so eligibility and the validation verdict stay one fact instead of being recomputed in the browser. Activation goes through `POST /api/sessions/<id>/router`, which delegates to the shared Runtime activation path, so the WebUI cannot reach a Router state the TUI or CLI could not: the profile validation, the non-blocking approval strategy, the idle fence, the source policy, and the durable mode entry all stay Runtime-owned. Channel sessions remain excluded by design, because WeChat and Feishu are source-forced to yolo and can never select Router.
- **A Router profile can opt into parallel base-workspace writers.** An ACP profile may set `allowParallelBaseWorkspaceWrites` to let write-role workers that target the session workspace run concurrently instead of taking it exclusively. The default stays exclusive, so every existing `settings.json` profile keeps its current behavior. This is explicit executable trust rather than a performance default: an external ACP Agent runs its own tools, so MothX cannot confine its writes to the declared `write_scope` and two workers can still touch the same file. The configured `maxConcurrentChildren` ceiling still applies, the Runtime still refuses a parallel writer whose declared `write_scope` overlaps a live base writer because that overlap is statically visible, and `mothx doctor` and the `/router` panel report the opt-in so the residual risk stays visible. Per-child worktrees plus `subagent_integrate` remain the safer default.
- **Router mode can now be activated from the TUI and CLI for a configured external ACP worker.** `/router` opens the ACP worker panel (list, add, edit, delete, and activate profiles); `/router <profile>` and `mothx --router --acp-agent <profile>` activate directly, and all of them call the same Runtime activation path: the profile must exist in `acpAgents`, be enabled, and use a non-interactive permission policy; the session must be idle and not source-forced to yolo; and the Router binding is persisted before the mode entry, so a failed activation leaves a non-Router session. The panel writes only through the single `config.SaveACPAgentProfiles` validator/owner, so an empty `command[0]`, duplicate ID, or malformed transport/URL is rejected before anything is stored. Activation only names the worker; Runtime records the non-blocking approval strategy from the profile and rejects a contradictory one. A hand-edited or legacy `defaultMode: router` is normalized to the read-only `plan` mode at load and resolution time instead of failing every new session's Agent construction; the fallback never widens to full access. A generic mode switch cannot select `router` without that binding: `router` is excluded from the Tab mode cycle and the `defaultMode` cycle, and Agent construction fails closed if a Router lead would be built with no eligible binding, so a persisted default or stale adapter value cannot produce a Router tool surface whose delegation can only fail. Every TUI mode write (`/mode`, the Tab cycle, `/systeminit`, a `defaultMode` settings change) now goes through the shared Runtime, so the adapter can no longer switch locally and then replay the old mode on reopen. A session reopened from another adapter or resumed without a mode flag replays its persisted mode, including Router. Editing `settings.json` remains supported and equally deliberate; external delegation is available through Router.

- **Router mode can delegate to a configured external ACP coding agent.** A Router-bound `delegate_subagent` launches one blocking external worker through the shared Runtime: Agent Core gets only an event/input proxy, while the Runtime owns profile policy, the bounded task contract, the single terminal event, and process containment. The Router lead sees streamed text, thought, tool, plan, and usage projections with `agent` identity; the blocking result carries bounded `worker` metadata labeled `worker-reported`, while the live child event projection keeps the complete streamed text and the lead receives only a bounded envelope. Remote `session/request_permission` requests are recorded through the shared decision ledger and answered immediately with the profile's `auto_allow_once`/`auto_reject` strategy, selecting only an offered one-time option. Cancellation sends `session/cancel`, answers pending requests as cancelled, and reaps the entire process tree (Unix process group, Windows Job Object). The external child transport has no persistence, provider, or adapter dependencies, and `mothx doctor` now validates profile shape and executable availability without launching a worker. An ACP profile's `maxConcurrentChildren` is enforced per session: read-only roles may fan out up to the configured ceiling, while an `implement` worker in a Runtime-managed per-child worktree may coexist with readers; a base-workspace writer remains exclusive. `mothx doctor` and the `/router` panel report the configured and enforced ceilings.

- **Router mode now supports asynchronous external ACP workers.** In addition to blocking `delegate_subagent`, Router exposes `subagent_spawn`, `subagent_status`, `subagent_wait`, `subagent_send`, and `subagent_destroy`. Spawn accepts the same bound `agent` allowlist and bounded role/scope/deliverable/verification contract and returns a manager handle immediately. The Runtime reserves the role-aware permit during child construction, so a spawn that conflicts with a live writer, or a writer that conflicts with any live reader, fails synchronously; read-only workers fan out to the profile ceiling. `subagent_wait(handle: ...)` waits on the existing manager status rather than requiring a team mailbox, and `subagent_send` continues the same remote session with one follow-up turn. External completions also enter the session mailbox keyed by the child handle. Local-only parameters (`member`, `mode`, `work_dir`, `worktree`, `tools`, `max_iterations`) are rejected; `subagent_answer` remains unavailable because ACP decisions use the parent `DecisionService`. Router and an Expert Team are mutually exclusive; a solo expert remains compatible.
- **Idle sessions now wake automatically when external workers complete.** The Runtime coalesces a burst of mailbox completions into one canonical lead Run (25ms debounce, 500ms cap), admits it through the shared submission coordinator and `ExecutionRuntime`, and seeds it with system-injected context instead of a fake user message. TUI and ACP project the same Run events; the Runtime writes the wake Run's terminal state once, and cancellation, approvals, and questions continue through the existing execution/decision paths. No adapter-local queue, timer, or event stream is created.
- **A Router session can bind an ordered allowlist of external ACP workers.** `/router id1,id2` and `mothx --router --acp-agent id1,id2` persist every selected profile with its own non-blocking approval strategy; the first profile is the default target. `delegate_subagent` and `subagent_spawn` accept any bound ID (a single worker remains a schema `const`, multiple workers become a schema `enum`), while configured-but-unbound profiles are rejected with correction context. `ACPChildBackend` resolves the requested profile instead of assuming the primary one, and the task contract records the actually selected target.
- **Router reuses one ACP process across isolated remote sessions, negotiates attachments, and exposes bounded filesystem/terminal bridges.** The Runtime connection pool initializes at most one process per profile/workdir and creates independent remote sessions, routing `session/update` and reverse permission requests by `sessionId`; shutdown closes the pool exactly once. Router tools accept Runtime input resource IDs in `attachments`; the Runtime verifies ownership, size, and SHA-256 before sending ACP image, audio, or embedded-resource blocks only when the Agent advertised the matching `promptCapabilities`. Embedded resources carry an opaque Runtime URN, never a `file://` path into a worktree that does not contain the session attachment. Unsupported content is disclosed with its Runtime resource ID and session-relative path instead of being silently dropped. When a Runtime Registry is attached, the client advertises `fs.readTextFile` and serves bounded UTF-8 reads through the same workspace-root and symlink fence as local read tools. A write-role task with a non-empty `write_scope` may use `fs/write_text_file`; profiles with `"terminal": true` get the contained terminal bridge. `additionalDirectories` is sent only when the Agent advertises that session capability.
- **ACP transport correctness and child history are now uniform.** Reverse `$/cancel_request` notifications cancel only the matching in-flight request and return ACP's `-32800`; `session/close` treats an already-closed/unknown session as success. `session/resume` is preferred for reconnect when advertised, with `session/load` as the history-replay fallback. Local child backends now persist to the same `session_child_runs` record as ACP children, including transcript, parent Run, workdir, status, and timestamps.
- **External ACP workers can use the standard remote transport.** An `acpAgents` profile may set `transport` to `websocket` or `http` and provide one administrator-configured `url`; omitting it keeps the existing contained stdio launch. The transport-only ACP client supports the remote RFD's cookie affinity, HTTP/2 requirement for `https://`, synchronous `initialize` plus asynchronous POST responses, one connection-scoped and one session-scoped SSE stream, `Acp-Connection-Id`/`Acp-Session-Id` routing (including reverse-request responses), bounded frames, JSON-RPC batch rejection, and DELETE shutdown. Remote profiles reject `command`, `environment`, embedded credentials, and scheme mismatches. The Runtime connection pool keys by transport and endpoint, so remote sessions reuse one initialized connection without sharing stdio workers; policy, decisions, child identity, canonical events, and terminalization stay Runtime-owned.
- **One ACP connection now serves read-only and write-role sessions together.** The pool no longer keys by the per-task write flag. A Registry-backed connection advertises `fs.writeTextFile` as part of its capability union even when the first task is read-only, while each session handler independently enforces its own task role, non-empty write scope, workspace fence, and symlink-resolved path. The same applies to terminal/read capabilities: the connection advertises what the Runtime can enforce, while a session that is not allowed to use it receives `-32601`. This preserves ACP's normal one-process/one-connection, many-isolated-sessions model instead of starting another worker for each role.
- **External ACP workers now honor managed per-child worktrees and retain bounded change sets.** A worktree resolved by `AgentManager` is passed to the ACP backend as trusted construction metadata instead of being ignored in favor of the session directory. The worker's `fs/read_text_file`, scoped `fs/write_text_file`, and `terminal/*` bridges use an isolated registry and sandbox rooted at that worktree, so they cannot read or write the main session workspace; the shared file lock and atomic write path remain in force. On every terminal path the Runtime captures a bounded snapshot with base/head revisions, changed-path statuses, a unified/binary patch, and bounded untracked content with SHA-256 digests. Migration 56 persists `worktree_id`, `base_revision`, `change_set_json`, and `change_set_error` in `session_child_runs`; truncated or failed snapshots are explicit and are never silently integrated. Router's `subagent_integrate` applies selected snapshots through one exclusive Runtime lane: it re-verifies the digest, successful terminal status, truncation state, and managed-worktree identity before applying the tracked patch and untracked bytes, returns git conflicts as structured evidence, and records `integration_id`, `integration_digest`, `integration_status`, `integration_error`, and `integrated_at` (migration 57). A multi-selection is transactional: when a later snapshot conflicts, snapshots applied by the same request are reversed and their evidence is updated. Uncapturable untracked entries (symlinks, special files, unreadable paths) mark the snapshot truncated instead of being silently omitted. Repeated `{handle, digest}` selections are idempotent.


- **Serve Web UI gains a dynamic multi-session workbench.** `/chat` now supports session tabs, up to four split panes with menu/drag splitting, per-pane composers and model/draft state, persisted layout, and a single-pane mobile projection. A single app-wide `session-stream` dispatcher is the only `/ws/runs` consumer and owns the SSE fallback, so background sessions keep streaming when another pane is closed. Panes render canonical `sessionRunStates` directly, and overflowing tabs are reachable through an explicit all-tabs menu; approvals and questions resolve in their owning pane's overlay, while background decisions surface only as tab and global attention badges without stealing focus; layout changes beyond the four-pane or tab limit are rejected with a visible reason. The legacy single-session fallback and its `?workbench=0`/Settings switch have been removed; `/chat` is always the workbench. A read-only Plan dock projects the focused session's latest plan message without adding storage, a tool, or a backend endpoint. Composer text survives tab switches; attachments with a `providerRef` are restored after a refresh, while dataUrl-only attachments prompt the user to select them again. Tab-strip dragging now reorders tabs instead of being mistaken for an edge split, and a second browser tab restores the shared last layout with last-write-wins recovery. Per-session scroll positions survive tab switches, and closing a tab whose task is still running shows a one-time background notice instead of silently dropping it. The workbench tab strip and icon-only toolbar are now compact and theme-aware, and the composer mirrors Desktop: the collapsed model+mode entry expands to plan/agent/yolo/os mode, Work/Code display mode, and provider/model/expert selection, while the session workdir sits in the chat header.

- **Serve gains an authenticated interactive terminal.** `features.terminal` exposes an xterm.js PTY panel backed by `internal/terminal` (creack/pty on Unix, ConPTY on Windows) over `/api/terminals` and `/ws/terminals/`. Terminals bind to the focused session's cwd, inherit the serve environment, support resize/replay/takeover, and are gated by loopback-or-authenticated-listener policy; they create no Run, transcript entry, or Runtime lease and remain outside the sandbox. On Linux the shell also carries `Pdeathsig`, so it cannot outlive the serve process, and a Windows-only ConPTY round-trip test is the real-runner gate. Terminal settings round-trip through `serve.json` saves, including an explicit `enabled: false`, shell, limits, and allowed origins. The status bar surfaces server-side output backpressure instead of treating it as a disconnect, and serve logs only terminal lifecycle metadata (create/exit/kill), never input or output.

- **The TUI status bar reports live generation speed.** While an agent streams, the footer now shows an estimated `tok/s` rate next to the elapsed time. The reading is derived from streamed output deltas over a short rolling window and disappears when no tokens are arriving, for example while a tool runs or an approval is pending. The loading line also shows the run's estimated generated-token total.

- **The TUI gains an in-place MCP manager, and remote MCP follows the current Streamable HTTP revision.** `/mcpmgr [project|global]` opens a panel over the scoped `mcp.json` that adds, edits, deletes, enables, and disables servers one field at a time (transport first, then name, endpoint or command, args, env, headers, and enabled state), replacing the previous `/init_mcp` and `/mcps` commands; changes are configuration-only and take effect after `/reload`. HTTP MCP clients now negotiate the protocol revision during `initialize`, send it in `MCP-Protocol-Version`, advertise `Accept: application/json, text/event-stream`, reject responses that are neither JSON nor `text/event-stream`, and no longer follow redirects on a configured endpoint, so credentials and request bodies cannot leak to another origin. `tools/call` results preserve `structuredContent` plus standard `resource`/`resource_link` blocks as model-readable text instead of dropping them.

### 🐛 Bug Fixes

- **Activating a Router ACP profile no longer freezes the TUI.** Activation previously ran `SessionRuntime.ActivateRouter` inline on the Bubble Tea update loop, so the Runtime's pre-activation session reload and the binding/mode writes blocked input, rendering, and cancellation for the whole reload — seconds on a large `sessions.db`. Activation now runs as a `tea.Cmd`: the update loop stays responsive, the panel shows an in-flight state, other panel keys and concurrent submissions are rejected until the result lands, and the adapter applies the Runtime-resolved mode and tool surface only through the completion message. Runtime remains the sole owner of validation, the idle fence, source policy, persistence, and write ordering.
- **A Router session can now spawn an external ACP worker.** The lead agent was only registered into the `AgentManager` when the adapter's multi-agent, delegate, or workflow capability was enabled, but Router mode installs the same delegation surface without any of those flags. Every spawn therefore failed with `create sub-agent: parent agent agent-master not found`, so a correctly configured and activated worker was never reached. The Runtime now owns the decision through `ManagerBackedToolsEnabled`, which counts Router alongside the ordinary capabilities, and every entry point (TUI, CLI, WebUI/API, ACP/Desktop) registers the lead through it. The TUI, WebUI, and ACP tool-group synchronization also resolve the mode from the Runtime instead of the adapter's own field, so a resumed or freshly activated Router session installs the Router delegation surface rather than the wrong one, and a Router session in ACP/Desktop gets the session-scoped manager its per-session worker binding requires.
- **Manager creation and tool-group synchronization after activation now have one Runtime entry point.** TUI, CLI, WebUI/API, ACP, and channels each open-coded the same "decide whether a manager is needed, build or reuse it, then install/remove the manager-backed tool groups" sequence, so a newly activated Router session could install `delegate_subagent` without a manager that owned the session (or reuse a stale manager after an expert transition). `SessionRuntime.ReconcileManagerBackedTools` now owns that whole decision: it applies the shared capability predicate (including a bound team and Router), builds only when required or explicitly rebuilt, preserves the current handle when construction fails, and reconciles the tool groups against the exact returned manager. Adapters supply only their capability policy, current handle, and construction factory; the TUI/CLI keep a manager for root-agent, ESM, and cron bookkeeping through an explicit `RequireManager` policy rather than a second implementation.

- **The TUI `/browser` command now actually enables browser automation.** The command previously only mutated the TUI-local tool registry, so the browser tool was silently removed again as soon as the first prompt created and bound a session: the shared Runtime reloaded its resources from the stale capability state and unregistered the tool before the Agent was built. The command now goes through the Runtime's own capability path, so the tool, its skill prompt, and the persisted session capability stay one fact. The Runtime also keeps the browser capability consistent across build, attach, capability updates, and resource refresh, and a browser toggle applied before the first prompt is persisted onto the session that prompt creates, so reopening that session keeps browser support enabled.

- **MCP servers no longer require a client restart, and a remote server pinned to an older protocol revision now connects.** Registering or editing an MCP server previously only wrote `mcp.json`, so the change reached the Agent only after a full client restart; the TUI `/mcpmgr` panel, the Serve Web UI `/api/mcp` endpoint, and the ACP `mothx/manage/mcp/set` method now reconnect the affected servers in place through the shared Runtime. MCP tools are owned by their server, so a reconnect replaces exactly that server's tool surface and removes the tools of a server that was deleted or disabled, without disturbing other servers' tools or the built-in ones. A run that is already in flight keeps the tool set it froze at build time, and the change applies to the next run. A failed reload leaves the previous working configuration connected instead of tearing it down. The protocol negotiation also no longer requires the newest revision: a server that answers `initialize` with `2025-06-18`, `2025-03-26`, or `2024-11-05` is accepted, and the `MCP-Protocol-Version` header is only sent for the revisions that define it. An unknown revision is still refused rather than falsely claimed as compatible.
- **Router's external ACP worker path is hardened.** The ACP client no longer closes its notification channel while a transport reader may be sending, so a worker exit or cancellation cannot panic on a concurrent send; the final response is also preferred over the transport's terminal error when both become ready together. Inbound frames are read in bounded fragments, rejecting an oversized line before allocating the whole payload. A single Router worker remains a schema `const`; a multi-worker binding becomes a bound-only `enum`. Local-child parameters (`mode`, `work_dir`, `worktree`, `tools`, `max_iterations`) are rejected instead of silently ignored. ACP permission cancellation now goes through `DecisionService`, failed resolution commits discard the in-memory pending row after recording a terminal one, output truncation preserves UTF-8, and Windows workers start suspended until they join the Job Object.
- **An asynchronously spawned external worker is no longer cancelled with the lead turn that created it.** A worker started through `subagent_spawn` derived its run context from the spawning lead's run, and that context is cancelled when the lead run reaches its terminal state. Every spawned worker was therefore cancelled the moment the lead finished its own turn, so a fan-out never actually ran to completion and the workers reported `canceled` instead of their result. The spawned worker now runs on a context detached from the lead's cancellation while keeping its values, and it stays cancellable through the manager, so `subagent_destroy` and Runtime shutdown still reach it. The blocking `delegate_subagent` path is unchanged: it is meant to end with the lead turn. This affects every entry point, because the lifecycle lives in the shared Agent Core rather than in one adapter.
- **External worker completions now carry their canonical child handle in the session mailbox.** A spawned ACP worker previously enqueued a completion with an empty member ID, making the mailbox item unactionable and its error hint point at a nonexistent local member. The completion now uses the child handle, is marked external, and points follow-up guidance at `subagent_status`/`subagent_send`; it still flows through the existing manager monitor and mailbox drain without a second child state machine.
- **External worker terminal metadata is no longer stale.** `subagent_status` and `subagent_wait` previously projected metadata captured when the child was created, so a finished worker never showed its `changeSetDigest`, truncation flag, or change-set capture error. The shared manager now refreshes backend metadata on status transitions, letting `subagent_integrate` use the exact evidence without relying only on the blocking delegate envelope.
- **TUI cancellation and quit paths no longer duplicate an automatic continuation's terminal state.** The Runtime owns the terminal transaction for a mailbox-wake Run, so the adapter's `finish` projection is now a no-op for that Run even when `abortPendingRequest`/`finalizeForQuit` reach it through `resetAgent`. Cancellation still stops the same `ExecutionRuntime` Run; only the second terminal write is removed.

- **ESM objective edits survive concurrent coordinator writes, and orphaned runs no longer block controls.** All ESM objective read-modify-write paths now run in `BEGIN IMMEDIATE` transactions, so a worker-progress write can no longer restore the objective text it read before a user edit committed. Pause/resume/clear also tolerate a canonical Run that has no live lease and is waiting for recovery, so an interrupted local admission can no longer leave an objective permanently uncontrollable. Terminal controls additionally report unsupported platforms as `501 terminal_unsupported` instead of `terminal_disabled`, and the Unix PTY build tag now matches the supported platform set so `aix` and other unsupported targets compile to the explicit `ErrUnsupported` implementation.

- **Interactive terminal lifecycle is race-free, follows focus, and always shows its safety boundary.** PTY read/wait loops now receive their handle at creation and the finish path clears the terminal handle under lock, eliminating both the data race and a nil-handle window that could panic when a short-lived shell exited during startup; listing/attaching a terminal reads its geometry through the locked `Size()` accessor instead of unsynchronized fields. Switching the focused workbench session now releases the old session's shell and creates one for the new cwd instead of leaving a stale terminal bound to the previous session, and a lost terminal id (for example after a serve restart) stops retrying and lets Reconnect create a fresh shell. The terminal status bar now continuously states that the shell is outside the sandbox and inherits the serve process user/environment, and surfaces the placeholder-auth-token warning reported by `/api/status`; the browser smoke test asserts the notices and the focus rebind. Closing a live shell now waits for the process to exit and only escalates to SIGKILL after the grace period instead of always sleeping two seconds, cookie-authenticated browsers no longer receive a long-lived terminal token, a rejected config update no longer applies terminal limits or kills shells before it rolls back, and the Windows ConPTY wrapper now closes handles exactly once and assigns the shell to a kill-on-close Job Object so background descendants cannot outlive the terminal.

- **Interactive terminal recovery, focus, and warnings are now complete.** The terminal dock always discloses that it shares the focused session's cwd with a possibly running Agent, and escalates the warning when the canonical execution snapshot is running locally or in another process. A page reload reattaches the detached shell recorded for that tab instead of leaking it and creating a second terminal, while an exited or lost terminal lets Reconnect create a fresh one. xterm's stylesheet is loaded, `@xterm/xterm`/`@xterm/addon-fit` are pinned exactly, and the PTY read loop waits for `cmd.Wait` before publishing an exit frame so a non-zero exit code is not reported as 0. Workbench tests also gained a 1000-operation property test, which fixed draft trajectory-mode persistence, focus repair after group removal/preset changes, exact split-weight clamping, paginated session-tab reconciliation, duplicate command-suggestion DOM ids, and mobile context-menu targeting.

- **A Draft created outside `/chat` survives the workbench remount.** Workbench hydration is now a one-shot startup step instead of re-reading `localStorage` whenever the lazily loaded Chat view mounts. A new Draft created from Sidebar/Sessions before the 300 ms persistence debounce fired could previously be replaced by the older stored layout; the in-memory workbench is now authoritative once the app has started, while a newly opened page still inherits the shared last layout. Browser and unit regression tests cover the remount and delayed-hydration paths.

- **Session content writes now have one authority, and split stores are repairable without data loss.** Every transcript write — messages, tool results, mode/thinking/title changes, and conversation turn boundaries — now resolves the persisted `sessions.content_store` instead of trusting this handle's in-memory mode, so a process that opened a session before another process migrated it adopts the committed event log instead of writing into the retired SQLite transcript or raising a false `session was modified by another process`. Opening a session is read-only: it no longer retires legacy payload rows, flips the store, or resets the log; legacy duplicate rows are removed only by a fenced, coverage-checked retire under a content lease, after a post-flip grace window. Rows a legacy build appends after the flip are detected as a split store and preserved. `mothx doctor` reports split sessions and, separately, sessions whose event-store turn boundaries address no matching turn marker (content lost before the event log owned it: those turns still read but cannot be forked, and `doctor` says so instead of reporting a clean store). `mothx doctor --repair-session-content [all|SESSION_ID]` adopts the uncovered delta, translates turn boundaries, and then retires the covered duplicate idempotently; `--json` reports per-session results. Architecture guards now reject a second content-store router, an open that reaches a store mutation, and any write branch on the in-memory mode. **Upgrade every MothX binary together and restart every running process (TUI, serve, and Desktop's bundled `mothx acp`) before repairing.** A mixed-build window cannot be prevented from the new build, but it no longer loses content: the new build keeps both stores until the repair entry adopts the difference.
