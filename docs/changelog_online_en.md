# Changelog (Current Version)

This file contains the changes for the **current version only**. The full history of all versions lives in [docs/en/changelog.md](en/changelog.md).

## v1.3.105-pre-4

### 💥 Behavior Changes

- **Non-hosted web search now uses DeepSeek Search/Fetch.** The old `webSearch` provider/type/model configuration that registered a provider-backed search tool was replaced by local `web_search` and `web_fetch` tools backed by DeepSeek's official `POST /v1/tools/search` and `POST /v1/tools/fetch` endpoints. Provider-native hosted search for OpenAI Responses is unchanged and takes precedence over the local `web_search` function. `webSearch` now configures `provider`, `baseUrl`, and `token` (with the provider API key as fallback); both tools are read-only and available in plan mode.

- **Tencent Yuanbao search backend added.** `webSearch.backend` selects `deepseek` (official Search/Fetch APIs) or `yuanbao` (Tencent Yuanbao SearchPro at `POST /SearchPro`). The Yuanbao backend sends `{"Query": ...}`, normalizes the returned `Pages` into title/URL/site/date/score/passage results, authenticates with `webSearch.token` or `${TENCENTCLOUD_WSA_APIKEY}`, and currently provides search only, so `web_fetch` remains available only with the DeepSeek backend.

- **The embedded Windows BusyBox now requires Windows 10 or later.** `busybox-windows-x86.exe` and `busybox-windows-x86_64.exe` are rebuilt from the fork's UTF-8 configs (`mingw64u_defconfig` for x86_64, `mingw32w_defconfig` for x86) and carry a UTF-8 application manifest (`activeCodePage=UTF-8`) together with `FEATURE_UTF8_INPUT`, `FEATURE_UTF8_CONSOLE`, `FEATURE_UTF8_AUTODETECT`, `FEATURE_UTF8_CHILD_ENV` and `UNICODE_SUPPORT`. Non-ASCII `sh -c` command text now reaches argv as UTF-8 instead of being down-converted to the system ANSI code page (GBK on zh-CN Windows), and the child environment keeps the UTF-8 baseline. The build sets `FEATURE_FAIL_IF_UTF8_MANIFEST_UNSUPPORTED=y`, so on Windows 7/8 BusyBox refuses to start; the `bash` tool then falls back to PowerShell exactly as it does whenever BusyBox is unavailable, so commands keep working (without the UTF-8 baseline). MothX continues to document Windows 10/11 as its supported Windows floor.

### 🐛 Bug Fixes

- **Captured Windows output is normalized at the capture boundary.** Child processes choose their pipe encoding independently — Python, Java, the C runtime and shell builtins often use the ANSI code page (GBK on zh-CN Windows) while Go, Rust, Node.js and most CLIs write UTF-8, and a single command can mix both. Rather than injecting a per-runtime environment variable, the `bash` tool now normalizes captured stdout/stderr through `platform.DecodeProcessOutput`: bytes that are not valid UTF-8 are decoded with the active code page, valid UTF-8 is trusted, and mixed output is resolved per maximal non-ASCII run. `MOTHX_WIN_OUTPUT_ENCODING=utf-8` forces UTF-8, and a numeric value such as `936` forces that code page.

- **Genuine UTF-8 text is no longer re-read as GBK.** The two encodings overlap on two-byte sequences, and the previous whole-block heuristic could decide once for an entire capture, re-decoding real UTF-8 text into unrelated Han characters (`Привет` → `袩褉懈胁械褌`, and a mixed line into `涓枃`). Ambiguity is now resolved per non-ASCII run and only when the stream carries no stronger UTF-8 signal: a stream whose UTF-8 reading contains CJK characters or any 3- or 4-byte sequence is never second-guessed, and only short runs of two-byte pairs are eligible. Byte-identical legacy fragments (for example a lone GBK `写`) still decode as before.

- **The extracted Windows BusyBox is refreshed when the embedded asset changes.** A previously extracted copy is compared with the embedded asset by SHA-256 and replaced atomically when they differ, so an upgraded MothX never keeps running an old shell. If a running BusyBox holds the executable image locked, the old copy is kept for that run and the refresh is retried on the next startup.

- **Stop handling now projects one Runtime decision across TUI and ACP, with race and recovery fixes.** ACP `session/cancel` snapshots the Run ID under `cancelMu` instead of racing the prompt handler, and the shared stop projection is bounded so it cannot stall the JSON-RPC read loop. TUI abort/reset moves the canonical stop and terminal write off the Bubble Tea update loop (quit waits for completion), so the UI no longer freezes; a canonical Run terminalized by another owner is adopted locally even when the terminal state differs, with the full terminal broadcast, instead of leaving the session permanently busy. A stopped recovered Responses background task now terminalizes as `cancelled` rather than `failed`.

- **Desktop shows and inspects sub-agents.** The chat header now reports how many sub-agents the session has and whether they are running; opening it shows a read-only panel listing every child with its status and renders one child's transcript with the ordinary chat message, tool-card, and reasoning styles. ACP adds the read-only `mothx/subagent/list` and `mothx/subagent/messages` projections plus the `subagentPanel` capability key, so Desktop no longer relies on isolated started/terminal cards.

## v1.3.105-pre-1

### ✨ New Features

- **New Gitee/Moark Model: `deepseek-v4.1-flash-1017`**
  - Added `deepseek-v4.1-flash-1017` to the `gitee` and `moark` providers, directly after `deepseek-v4.1-flash` and with identical parameters: a 1M context window, reasoning support, and text+image input; no default max_tokens is sent.

- **New MiniMax Model: `MiniMax-M3.1-Flash`**
  - Added `MiniMax-M3.1-Flash` to the `minimax` provider: reasoning support with thinking intensity via the Anthropic-compatible `output_config.effort` scale (adaptive thinking format; `minimal` and `low` map to `low`, the rest map one-to-one to `medium`/`high`/`xhigh`/`max`), a 1M context window, and text+image+video input. The preset declares a 1M output ceiling (the full context window), while requests still use MothX's normal output-token default unless you raise it explicitly.

- **Volcengine Retired Models Removed.** Volcengine has taken `kimi-k2.7-code`, `doubao-seed-2.1-turbo`, and `minimax-m3` offline, so the `volcengine`, `volcengine-agentplan`, and `volcengine-codingplan` presets no longer list them (including the standard channel's `doubao-seed-2-1-turbo-260628` snapshot). The same IDs remain available on other providers such as Gitee/Moark. Because preset order is also the fallback when no default model is configured, an unconfigured standard `volcengine` session now defaults to `doubao-seed-evolving` instead of the retired snapshot.

- **DeepSeek V4.1 Thinking Intensity.** DeepSeek V4.1 models in the Gitee/Moark and Volcengine presets now use the verified `reasoning_effort` parameter instead of only a thinking switch. MothX's `minimal`, `low`, `medium`, `high`, `xhigh`, and `max` levels map one-to-one to the gateway scale, while `off` sends `none` to disable these gateways' think-by-default behavior. Gitee/Moark and Volcengine Agent Plan were validated live across the complete accepted enum. All DeepSeek V4.1 model IDs default to this format, including third-party gateways; a deployment that only accepts the older thinking switch can opt out with `thinkingFormat: "thinking-only"`.

- **Unsupported `reasoning_effort` falls back automatically.** If an OpenAI-compatible endpoint rejects `reasoning_effort`, MothX retries immediately without the field (keeping the DeepSeek V4.1 thinking switch), shows the reason in the retry notice, and records `thinkingFormat: "thinking-only"` plus `supportsReasoningEffort: false` for that model so later runs omit it. The fallback does not consume a retry attempt.

- **Sessions reject unusable working directories early.** `internal/session` is the single owner of working-directory validation, with the Runtime API delegating to it. Session creation, reopening, rebinding, ACP `mothx/session/setWorkDir`, and channel session resolution now require an existing absolute directory before persisting or assembling sandbox and tool resources. An ACP same-directory request no longer detaches a usable runtime when its directory has disappeared, and a channel run validates the bound session's persisted cwd rather than the platform default.
- **Desktop uses an explicit draft-directory model.** The legacy workspace-default fallback and settings panel were removed. Quick-start drafts receive one process-local `mkdtemp` scratch directory, while a New Task draft remains unset until its native picker or worktree action supplies a directory. Picker history is only a convenience for the next dialog; draft state carries a generation so a stale quick-start, picker, or ACP completion cannot overwrite a newer New Task.
- **Runtime coordinates local session submissions.** `SessionRuntime` owns one `(database identity, session ID)` FIFO `SubmissionCoordinator`, and `ExecutionRuntime.Completion` is the authoritative completion barrier. TUI queued input, ACP prompt admission, Channel/Cron/ESM/Knowledge admission handoffs, shutdown, cancellation, and structured local/external busy classification now share that lifecycle instead of polling lease errors or starting a successor from an Agent finish event.

### 🐛 Bug Fixes

- **Rotating a bound channel session preserves its durable directory.** Rotation inherits the existing session's persisted cwd instead of falling back to the platform default, and its fenced compare-and-set compares canonical paths so an equivalent stored form such as a trailing separator still succeeds while a real concurrent change is rejected.
- **Feishu tool-image cleanup is concurrency-safe.** Each delivery materializes images beneath a unique private temporary directory and removes the whole directory on every exit path, preventing parallel runs from collecting one another's files and leaving no image bytes behind in the work directory.
- **Session EventStore migration has one unified entry point.** Migrating an old session to the EventStore used to happen only from `SessionRuntime.BindSession`, so entry points that assemble sessions directly — ACP/Desktop, channels, ESM, and background runs — left old sessions on the legacy SQLite transcript and kept new sessions on the `sqlite` content store. `BindSession`, `AttachSessionResources`, and `Builder.Build` now call the same migration entry point, `Manager.MigrateToEventStore`, with no per-site wrapper or special handling: an existing session is exported to the session-scoped EventStore and a new one is flipped to it regardless of which adapter opened it, with no divergence in content ownership. The entry is now safe to call unconditionally — while another owner is running the session it is a successful no-op instead of an attach-blocking error, the self-consistent legacy store keeps serving, and a later idle attach completes the migration; only corrupt or unreplayable legacy data fails closed.
- **Stopping a session no longer fails while its run is terminalizing.** A terminal write that failed after the durable Run entered the committed `terminalizing` window left its row in a state only a terminal transition may advance, yet the Web UI stop path still tried to force `terminalizing` -> `cancelling`, which the run store rejects — so the request returned `persist run cancellation: invalid session run transition "terminalizing" -> "cancelling"` and the run looked permanently uncancellable. `ExecutionRuntime.CancelDurable` and the shutdown cancel path now detect a prepared/terminalizing terminal transaction, skip the illegal cancelling write, accept the cancellation (still cancelling the loop), and restart the prepared terminal write when its retry had stopped, so an interrupted run can still reach a terminal state.
- **Appending to a session's EventStore is no longer quadratic in transcript size.** EventStore appends used to re-read the whole log several times per batch — a health inspection, an idempotency scan, a next-sequence scan, and a commit-time validity scan — so append cost grew with the session's accumulated content (512 entries: 3.8 ms → 178 ms per batch, 5.7 s cumulative) while the legacy SQLite path stayed flat. The health gate now trusts the process-local append-state cache whenever it is fresh for the current physical revision and checks only that every SQLite intent is committed; `NextSequence` reads the cached cursor; the idempotency probe uses the projection index and reads the full committed transcript only on a real retry; and `CommitEventIntent` accepts the just-fsynced batch instead of rescanning. Appends are now constant-time in transcript size (same probe: ~3 ms per batch, 0.30 s cumulative, about 19x faster), with the intent/lease protocol, fencing, and recovery verification unchanged. A deterministic regression test pins that appending to a warm session performs no whole-log scans.
- **Opening a brand-new Web UI session no longer reports `session_not_found`.** A server-allocated Web UI session is persisted only when its first run starts, but the run-event, capability-event, and sub-agent lookups rejected that still-unpersisted id, so the Web UI surfaced `session_not_found` while creating a session. Those three lookups now project an empty result for an allocated id — matching the trajectory, capabilities, runtime, and message lookups — while an arbitrary unknown id is still rejected.
- **EventStore migration is bounded and self-healing.** The one-time export of an old session's transcript is now written in batches of 64 entries instead of a single unbounded batch, so one fsync and one SQLite projection transaction stay bounded no matter how large the transcript is. The export also no longer wedges on stale or interrupted state: because the content store stays SQLite until the flip, any EventStore bytes or intents a previous interrupted attempt left behind are discarded and the transcript is re-exported, instead of refusing the migration and failing the attach.
