# Changelog (Current Version)

This file contains the changes for the **current version only**. The full history of all versions lives in [docs/en/changelog.md](en/changelog.md).

## v1.3.108

### ✨ New Features

- **Serve Web UI gains a dynamic multi-session workbench.** `/chat` now supports session tabs, up to four split panes with menu/drag splitting, per-pane composers and model/draft state, persisted layout, and a single-pane mobile projection. A single app-wide `session-stream` dispatcher is the only `/ws/runs` consumer and owns the SSE fallback, so background sessions keep streaming when another pane is closed. Panes render canonical `sessionRunStates` directly, and overflowing tabs are reachable through an explicit all-tabs menu; approvals and questions resolve in their owning pane's overlay, while background decisions surface only as tab and global attention badges without stealing focus; layout changes beyond the four-pane or tab limit are rejected with a visible reason. The legacy single-session fallback and its `?workbench=0`/Settings switch have been removed; `/chat` is always the workbench. A read-only Plan dock projects the focused session's latest plan message without adding storage, a tool, or a backend endpoint. Composer text survives tab switches; attachments with a `providerRef` are restored after a refresh, while dataUrl-only attachments prompt the user to select them again. Tab-strip dragging now reorders tabs instead of being mistaken for an edge split, and a second browser tab restores the shared last layout with last-write-wins recovery. Per-session scroll positions survive tab switches, and closing a tab whose task is still running shows a one-time background notice instead of silently dropping it. The workbench tab strip and icon-only toolbar are now compact and theme-aware, and the composer mirrors Desktop: the collapsed model+mode entry expands to plan/agent/yolo/os mode, Work/Code display mode, and provider/model/expert selection, while the session workdir sits in the chat header.

- **Serve gains an authenticated interactive terminal.** `features.terminal` exposes an xterm.js PTY panel backed by `internal/terminal` (creack/pty on Unix, ConPTY on Windows) over `/api/terminals` and `/ws/terminals/`. Terminals bind to the focused session's cwd, inherit the serve environment, support resize/replay/takeover, and are gated by loopback-or-authenticated-listener policy; they create no Run, transcript entry, or Runtime lease and remain outside the sandbox. On Linux the shell also carries `Pdeathsig`, so it cannot outlive the serve process, and a Windows-only ConPTY round-trip test is the real-runner gate. Terminal settings round-trip through `serve.json` saves, including an explicit `enabled: false`, shell, limits, and allowed origins. The status bar surfaces server-side output backpressure instead of treating it as a disconnect, and serve logs only terminal lifecycle metadata (create/exit/kill), never input or output.

### 🐛 Bug Fixes

- **ESM objective edits survive concurrent coordinator writes, and orphaned runs no longer block controls.** All ESM objective read-modify-write paths now run in `BEGIN IMMEDIATE` transactions, so a worker-progress write can no longer restore the objective text it read before a user edit committed. Pause/resume/clear also tolerate a canonical Run that has no live lease and is waiting for recovery, so an interrupted local admission can no longer leave an objective permanently uncontrollable. Terminal controls additionally report unsupported platforms as `501 terminal_unsupported` instead of `terminal_disabled`, and the Unix PTY build tag now matches the supported platform set so `aix` and other unsupported targets compile to the explicit `ErrUnsupported` implementation.

- **Interactive terminal lifecycle is race-free, follows focus, and always shows its safety boundary.** PTY read/wait loops now receive their handle at creation and the finish path clears the terminal handle under lock, eliminating both the data race and a nil-handle window that could panic when a short-lived shell exited during startup; listing/attaching a terminal reads its geometry through the locked `Size()` accessor instead of unsynchronized fields. Switching the focused workbench session now releases the old session's shell and creates one for the new cwd instead of leaving a stale terminal bound to the previous session, and a lost terminal id (for example after a serve restart) stops retrying and lets Reconnect create a fresh shell. The terminal status bar now continuously states that the shell is outside the sandbox and inherits the serve process user/environment, and surfaces the placeholder-auth-token warning reported by `/api/status`; the browser smoke test asserts the notices and the focus rebind. Closing a live shell now waits for the process to exit and only escalates to SIGKILL after the grace period instead of always sleeping two seconds, cookie-authenticated browsers no longer receive a long-lived terminal token, a rejected config update no longer applies terminal limits or kills shells before it rolls back, and the Windows ConPTY wrapper now closes handles exactly once and assigns the shell to a kill-on-close Job Object so background descendants cannot outlive the terminal.

- **Interactive terminal recovery, focus, and warnings are now complete.** The terminal dock always discloses that it shares the focused session's cwd with a possibly running Agent, and escalates the warning when the canonical execution snapshot is running locally or in another process. A page reload reattaches the detached shell recorded for that tab instead of leaking it and creating a second terminal, while an exited or lost terminal lets Reconnect create a fresh one. xterm's stylesheet is loaded, `@xterm/xterm`/`@xterm/addon-fit` are pinned exactly, and the PTY read loop waits for `cmd.Wait` before publishing an exit frame so a non-zero exit code is not reported as 0. Workbench tests also gained a 1000-operation property test, which fixed draft trajectory-mode persistence, focus repair after group removal/preset changes, exact split-weight clamping, paginated session-tab reconciliation, duplicate command-suggestion DOM ids, and mobile context-menu targeting.

- **A Draft created outside `/chat` survives the workbench remount.** Workbench hydration is now a one-shot startup step instead of re-reading `localStorage` whenever the lazily loaded Chat view mounts. A new Draft created from Sidebar/Sessions before the 300 ms persistence debounce fired could previously be replaced by the older stored layout; the in-memory workbench is now authoritative once the app has started, while a newly opened page still inherits the shared last layout. Browser and unit regression tests cover the remount and delayed-hydration paths.
