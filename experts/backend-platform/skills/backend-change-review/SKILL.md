# 后端变更评审

## 何时使用

在合并后端端点、数据访问、迁移、队列或运行时行为变更前使用。

## 检查清单

### 契约与兼容性

- 端点、请求/响应字段、错误码是否显式且与调用方一致；
- 是否向后兼容；破坏性变更是否有弃用窗口与迁移路径；
- 分页、幂等、超时、重试语义是否写清，而不是留给调用方猜。

### 数据与迁移

- 迁移是否 expand-contract、可重入、可暂停、可回滚；
- 大表 DDL/回填是否说明锁级别、批次与预计耗时；
- 事务边界是否对应业务不变量，是否存在长事务或跨服务事务；
- 查询是否避免 N+1，索引是否有执行计划依据。

### 运行时

- 每个外部依赖是否有超时、重试上限、退避与熔断；
- 副作用操作是否幂等或可补偿；
- 并发共享状态是否有明确同步/所有权，队列与 goroutine/线程是否有界；
- 配置是否有默认值、校验与启动失败策略。

### 验证

- 成功、失败、边界、幂等与重试路径是否有测试；
- 是否报告命令、退出码、关键输出与覆盖缺口；
- 未验证项是否明确标注，而不是用“测试通过”代替行为正确。

## 输出格式

- 结论：可合并 / 需修改 / 证据不足；
- 阻塞项：位置、触发条件、影响、修复建议；
- 建议项：非阻塞改进；
- 验证证据与未覆盖范围。

## 反模式

- 用一个 happy-path 测试证明整个端点安全；
- 关闭校验或放宽断言让测试变绿；
- 在没有执行计划的情况下声称“加了索引就快了”。
