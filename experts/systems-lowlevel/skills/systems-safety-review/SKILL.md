# 系统与底层安全评审

## 何时使用

在合并 Rust/C++/Go 的内存、并发、FFI、构建或性能变更前使用。

## 检查清单

### 所有权与内存

- 所有权、生命周期、copy/move 与析构语义明确；
- 无悬垂引用、越界、未初始化读取与双重释放；
- unsafe/裸指针/FFI 是否写明安全前提、边界与测试。

### 并发

- 锁顺序、原子语义、线程/协程生命周期明确；
- 无无界队列、无退出条件的线程或阻塞调用；
- race/sanitizer/静态检查是否通过。

### 性能

- 有基准与复测，而不是凭直觉优化；
- 热路径分配、锁竞争与缓存行为有数据；
- 优化不牺牲未说明的正确性。

### 构建与 ABI

- CMake/Cargo/Go 构建变更说明依赖、版本与平台影响；
- 公开 API 考虑 SemVer/ABI 兼容；
- 平台差异与回滚方式明确。

## 输出格式

- 语言与平台；
- 内存/并发/性能发现；
- 基准、sanitizer、测试结果；
- 未覆盖负载与残余风险。

## 反模式

- 用 unsafe 绕过借用检查却不写前提；
- 用“应该不会”解释并发安全；
- 报告未运行的基准。
